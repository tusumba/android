# android

Android-приложение Tusumba для посетителей и организаторов мероприятий.

**Ответственный:** Дмитрий Гузенков (каркас проекта #18894, сетевой слой #18895).

**Участники:** Александр Голуб (каталог мероприятий, #18896), Руслан Солихов (вход и регистрация, #18897). Дизайн-система и вайрфреймы: Борис Янин (#18898, #18899).

## Что делает

- каталог и страница мероприятия, вход и регистрация;
- покупка билета, показ билета с QR-кодом, записи на мероприятия;
- друзья и приглашения, уведомления (push через FCM);
- функции организатора: создание и редактирование мероприятий, продажа билетов, статистика, сканирование билетов;
- кнопка «Показать на карте» открывает внешние карты.

Кабинет модератора в Android-приложении не делается, он только в веб-клиенте.

## Стек

Kotlin, Jetpack Compose, Retrofit + kotlinx.serialization. Клиент API генерируется из OpenAPI. В качестве DI выбран Hilt.

## Запуск

Нужны JDK 17 и Android SDK (Platform 34, Build-Tools 34.0.0).
Укажите SDK через `ANDROID_HOME` или `sdk.dir` в локальном `local.properties`.

```bash
bash ./gradlew assembleDebug testDebugUnitTest
bash ./gradlew installDebug
```

## Каталог мероприятий через API (#19058)

Каталог использует сгенерированный клиент Events и настоящий `GET /v1/events`.
`ApiEventsRepository` преобразует ответ в существующую модель карточки;
`CatalogViewModel` управляет фильтрами и страницами. Данные в экран не зашиты.
Общий API-стенд пока не предоставлен, поэтому для локальной проверки есть отдельная
HTTP-заглушка. Проверка с настоящим Events на общем стенде остаётся шагом приёмки.

- Карточки: название, дата, место, цена, статус подтверждения. Деньги приходят
  в копейках, отображаются в рублях.
- Тип: все / бесплатные / платные (`is_free`).
- «Дата, место и статус» раскрывает границы дат, часть адреса и статусы.
  Статусов можно выбрать несколько; все фильтры передаются одновременно.
- Фильтры применяются автоматически. Для текста задержка 300 мс после ввода.
  При изменении фильтра отменяется старый запрос и загружается первая страница.
  «Сбросить» очищает фильтры и возвращает исходную выдачу.
- Страницы по 20 карточек, начиная с `page=1`. «Найдено» показывает серверный `total`;
  «Показать ещё» добавляет страницу. Ошибка дозагрузки сохраняет карточки,
  повтор запрашивает ту же страницу. API сортирует мероприятия: ближайшие выше.
- По умолчанию Events показывает мероприятия с сегодняшней даты по Новосибирску.
  Для прошедших событий задайте начальную дату в прошлом.
- Детали, профиль, вход и секции сохраняют существующие переходы.
  Подключение экрана деталей к API не входит в #19058.

Спецификация: [Events & Clubs](specs/events.yaml).
Требования: [#18110](https://ai.nsu.ru/issues/18110), [#18111](https://ai.nsu.ru/issues/18111).
Оформление основано на [вайрфрейме #18899](https://github.com/tusumba/design/blob/c94c8d65613c8365c5aab1f21bdd55d2a66e7f6e/split%201/Tusumba_Wireframes_Preview.html).

Поиск сохранён и передаёт `query` по OpenAPI. В проверенной реализации
`events-service/main` этот параметр пока не обрабатывается; поиск относится
к отдельному требованию #18112. Локальная заглушка поддерживает `query` для проверки клиента.

### Локальный запуск без стенда

Нужен Python 3.9+, без дополнительных пакетов. Из корня проекта:

```bash
python3 scripts/catalog_stub.py
```

Заглушка слушает только `127.0.0.1:8080` и содержит 48 демонстрационных событий.
Даты вычисляются относительно дня запуска. По умолчанию доступны 24 будущих события:
две страницы (20 + 4). Прошедшие имеют статусы «Состоялось» / «Не состоялось»
и доступны при выборе соответствующего диапазона дат.

С запущенным Android-эмулятором выполните в другом терминале:

```bash
bash ./gradlew --no-daemon assembleDebug testDebugUnitTest
adb -e install -r app/build/outputs/apk/debug/app-debug.apk
adb -e shell am force-stop com.example.tusumba
adb -e shell am start -n com.example.tusumba/.MainActivity
```

Debug-сборка уже использует `http://10.0.2.2:8080/` — адрес компьютера из эмулятора.
Когда появится настоящий стенд, укажите URL шлюза до `/v1`:

```bash
bash ./gradlew installDebug -PapiBaseUrl=https://stand.example.org/
```

Параметр применяется к debug-сборке. URL release-сборки пока остаётся существующей
заглушкой `https://api.tusumba.example/` до предоставления адреса стенда.

### Проверка фильтров и состояний

1. Откройте каталог: проверьте загрузку, карточки, «Найдено: 24».
2. «Показать ещё» добавляет последние четыре карточки, кнопка исчезает.
3. Выберите «Платные», раскройте дополнительные фильтры, введите «парк» в место,
   выберите «Подтверждено» и «Не подтверждено», ограничьте даты.
   Останутся платные события в парке, соответствующие всем выбранным фильтрам.
4. Введите несуществующее место: «По выбранным фильтрам ничего не найдено.».
   «Сбросить фильтры» возвращает полный каталог с первой страницы.
5. Конечная дата раньше начальной вызывает сообщение о диапазоне; запрос не отправляется.
6. Проверьте переход к деталям и возврат, профиль, секции, светлую и тёмную темы.

Для других состояний остановите заглушку через Ctrl+C и запустите один вариант:

```bash
python3 scripts/catalog_stub.py --scenario empty
python3 scripts/catalog_stub.py --scenario error
python3 scripts/catalog_stub.py --fail-page 2
python3 scripts/catalog_stub.py --delay 2
```

После смены сценария перезапустите приложение. В `empty` показывается
«мероприятий пока нет.». В `error` проверьте ошибку загрузки; с выбранными фильтрами —
«Не удалось применить фильтры. Попробуйте позже.». Чтобы проверить восстановление,
перезапустите заглушку без параметров и нажмите «Повторить».
`--fail-page 2` проверяет сохранение карточек при ошибке дозагрузки.
Старый параметр сборки `catalogMockScenario` больше не используется: каталог
всегда работает по HTTP, сценарий выбирается на стороне заглушки.

Тесты MockWebServer проверяют HTTP-параметры, статусы, пагинацию, декодирование и ошибки.
Тесты ViewModel — отмену запросов, смену/сброс фильтров, повтор страниц;
Compose-тесты — элементы управления и состояния экрана.

## Каталог и страницы секций (#19060)

Пункт «Секции» в нижней навигации открывает каталог из Events & Clubs.
Поиск по части названия передаётся в `GET /v1/clubs?query=...`. Очистка возвращает
исходный каталог. «Показать ещё» загружает следующую страницу.

Карточка открывает `GET /v1/clubs/{id}`. На странице показаны название, описание,
расписание, место встреч, контакты и мероприятия из `GET /v1/events?club_id=...`.
Мероприятия используют существующие карточки и переход к деталям мероприятия.
При HTTP 404 отображается сообщение «Секция недоступна.»

По умолчанию debug-сборка использует локальный шлюз `http://10.0.2.2:8080/`.
Для другого стенда замените адрес в следующей команде.

```bash
bash ./gradlew installDebug -PapiBaseUrl=https://stand.example.org/
```

Параметр задаёт базовый адрес шлюза с префиксом до `/v1`.
Для локального HTTP-сервера в debug разрешён cleartext-трафик.
Ошибки каталога, поиска, страницы и списка мероприятий имеют отдельные действия
повторной загрузки.

## Работа со спецификациями
Для добавления новых спецификаций необходимо положить файл .yaml в папку specs и указать в файле app/build.gradle.kts аналогичный код как и для прочих спецификаций (смотри конец файла).
При изменении спецификации просто измени соответствующий файл в specs.
Все файлы автоматически сгенерируются при сборке проекта.

## Правила работы

Ветки, коммиты, pull request и code review описаны в [CONTRIBUTING.md](https://github.com/tusumba/.github/blob/main/CONTRIBUTING.md). Коротко:

- ветка называется `feature/<номер задачи Redmine>-<пара слов>`, например `feature/18901-login`;
- номер задачи указывается в каждом коммите и в названии PR;
- в `main` изменения попадают только через PR с одним одобрением и зелёным CI, прямой push и force push запрещены.
