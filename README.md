# android

Android-приложение Tusumba для посетителей и организаторов мероприятий.

**Ответственный:** Дмитрий Гузенков (каркас проекта #18894, сетевой слой #18895).

**Участники:** Александр Голуб (каталог мероприятий, #18896), Руслан Солихов (вход и регистрация, #18897). Дизайн-система и вайрфреймы: Борис Янин (#18898, #18899).

## Что делает

- каталог и страница мероприятия, вход и регистрация;
- покупка билета, показ билета с QR-кодом, записи на мероприятия;
- друзья и приглашения, уведомления (push через FCM);
- функции организатора: создание и редактирование мероприятий, продажа билетов, статистика, сканирование билетов;
- кнопка «Показать на карте» открывает внешние карты.

Кабинет модератора в Android-приложении не делается, он только в веб-клиенте.

## Стек

Kotlin, Jetpack Compose, Retrofit + kotlinx.serialization. Клиент API генерируется из OpenAPI. В качестве DI выбран Hilt.

## Запуск

Нужны JDK 17 и Android SDK (Platform 34, Build-Tools 34.0.0).
Укажите SDK через `ANDROID_HOME` или `sdk.dir` в локальном `local.properties`.

```bash
bash ./gradlew assembleDebug testDebugUnitTest
bash ./gradlew installDebug
```

## Каталог на моковых данных (#18896)

Экран повторяет мобильный каталог из [вайрфрейма #18899, preview v1.3](https://github.com/tusumba/design/blob/c94c8d65613c8365c5aab1f21bdd55d2a66e7f6e/split%201/Tusumba_Wireframes_Preview.html).
Демонстрационные события взяты из этого же макета и записаны в форме `EventCard` из
`specs/events.yaml` (`GET /v1/events`): дата без времени, `place_address`, `is_free`,
цена `Money` в копейках и статус подтверждения.

- Поиск по части названия (`query`) и чипы «Бесплатные» / «Платные» (`is_free`, тип мероприятия
  по контракту) фильтруют данные локально, без запросов API.
- «Подробнее» передаёт ID карточки в существующий экран мероприятия.
- «Войти» и «Профиль» используют существующий переход к профилю. Формы входа
  реализованы в #18897, каталог секций подключён к API в #19060.
  Пункт «Друзья» пока отключён.
- Цвета light/dark и типографика Material 3 из макета применяются только к каталогу.
  Общая тема приложения и экраны остальных задач не меняются.

`EventsRepository` — контракт источника данных. `MockEventsRepository` содержит только
моки; `CatalogViewModel` управляет загрузкой и фильтрами; Compose получает `CatalogUiState`
и обработчики действий. Для подключения API достаточно реализовать `EventsRepository`
и заменить binding в `CatalogModule`, сохранив модель `CatalogEvent`.

### Проверка состояний

Обычная debug-сборка показывает skeleton загрузки, затем шесть карточек. Введите
«мастерская», выберите «Платные» и проверьте карточку с ценой 900 ₽. Несуществующий запрос
покажет пустую выдачу; «Сбросить фильтры» вернёт список.

Для воспроизводимой пустой выдачи или ошибки источника есть параметры debug-сборки:

```bash
bash ./gradlew installDebug -PcatalogMockScenario=empty
bash ./gradlew installDebug -PcatalogMockScenario=error
bash ./gradlew installDebug -PcatalogMockScenario=success
```

После установки перезапустите приложение. В режиме `error` кнопка «Повторить» снова
показывает загрузку, затем ту же ошибку. Параметр не добавляет элементы отладки в
интерфейс; release-сборка всегда использует обычные моки.

Проверьте также переход к деталям и возврат в каталог, открытие профиля, светлую и
тёмную системные темы. Compose Preview содержит загрузку, пустую выдачу и ошибку.
Unit-тесты проверяют моки, фильтрацию, отмену/повтор загрузки и подмену репозитория;
Compose-тесты на Robolectric проверяют поля карточки, поиск и обработчики действий.

## Каталог и страницы секций (#19060)

Пункт «Секции» в нижней навигации открывает каталог из Events & Clubs.
Поиск по части названия передаётся в `GET /v1/clubs?query=...`; очистка возвращает
исходный каталог. «Показать ещё» загружает следующую страницу.

Карточка открывает `GET /v1/clubs/{id}`. На странице показаны название, описание,
расписание, место встреч, контакты и мероприятия из `GET /v1/events?club_id=...`.
Мероприятия используют существующие карточки и переход к деталям мероприятия.
HTTP 404 показывает «Секция недоступна.».

По умолчанию debug-сборка использует локальный шлюз `http://10.0.2.2:8080/`.
Для другого стенда замените адрес в следующей команде.

```bash
bash ./gradlew installDebug -PapiBaseUrl=https://stand.example.org/
```

Параметр задаёт базовый адрес шлюза с префиксом до `/v1`.
Для локального HTTP-сервера в debug разрешён cleartext-трафик.
Ошибки каталога, поиска, страницы и списка мероприятий имеют отдельные действия
повторной загрузки.

## Работа со спецификациями
Для добавления новых спецификаций необходимо положить файл .yaml в папку specs и указать в файле app/build.gradle.kts аналогичный код как и для прочих спецификаций (смотри конец файла).
При изменении спецификации просто измени соответствующий файл в specs.
Все файлы автоматически сгенерируются при сборке проекта.

## Правила работы

Ветки, коммиты, pull request и code review описаны в [CONTRIBUTING.md](https://github.com/tusumba/.github/blob/main/CONTRIBUTING.md). Коротко:

- ветка называется `feature/<номер задачи Redmine>-<пара слов>`, например `feature/18901-login`;
- номер задачи указывается в каждом коммите и в названии PR;
- в `main` изменения попадают только через PR с одним одобрением и зелёным CI, прямой push и force push запрещены.
