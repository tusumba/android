# android

Android-приложение Tusumba для посетителей и организаторов мероприятий.

**Ответственный:** Дмитрий Гузенков (каркас проекта #18894, сетевой слой #18895).

**Участники:** Александр Голуб (каталог мероприятий, #18896), Руслан Солихов (вход и регистрация, #18897). Дизайн-система и вайрфреймы: Борис Янин (#18898, #18899).

## Что делает

- каталог и страница мероприятия, вход и регистрация;
- покупка билета, показ билета с QR-кодом, записи на мероприятия;
- друзья и приглашения, уведомления (push через FCM);
- функции организатора: создание и редактирование мероприятий, продажа билетов, статистика, сканирование билетов;
- кнопка «Показать на карте» открывает внешние карты.

Кабинет модератора в Android-приложении не делается, он только в веб-клиенте.

## Стек

Kotlin, Jetpack Compose, Retrofit + kotlinx.serialization. Клиент API генерируется из OpenAPI. В качестве DI выбран Hilt.

## Запуск

Нужны JDK 17 и Android SDK (Platform 34, Build-Tools 34.0.0).
Укажите SDK через `ANDROID_HOME` или `sdk.dir` в локальном `local.properties`.

```bash
bash ./gradlew assembleDebug testDebugUnitTest
bash ./gradlew installDebug
```

## Каталог мероприятий через API (#19058)

Каталог использует сгенерированный клиент Events и настоящий `GET /v1/events`.
`ApiEventsRepository` преобразует ответ в существующую модель карточки;
`CatalogViewModel` управляет фильтрами и страницами. Данные в экран не зашиты.
Общий API-стенд пока не предоставлен, поэтому для локальной проверки есть отдельная
HTTP-заглушка. Проверка с настоящим Events на общем стенде остаётся шагом приёмки.

- Карточки: название, дата, место, цена, статус подтверждения. Деньги приходят
  в копейках, отображаются в рублях.
- Тип: все / бесплатные / платные (`is_free`).
- «Дата, место и статус» раскрывает границы дат, часть адреса и статусы.
  Статусов можно выбрать несколько; все фильтры передаются одновременно.
- Фильтры применяются автоматически. Для текста задержка 300 мс после ввода.
  При изменении фильтра отменяется старый запрос и загружается первая страница.
  «Сбросить» очищает фильтры и возвращает исходную выдачу.
- Страницы по 20 карточек, начиная с `page=1`. «Найдено» показывает серверный `total`;
  «Показать ещё» добавляет страницу. Ошибка дозагрузки сохраняет карточки,
  повтор запрашивает ту же страницу. API сортирует мероприятия: ближайшие выше.
- По умолчанию Events показывает мероприятия с сегодняшней даты по Новосибирску.
  Для прошедших событий задайте начальную дату в прошлом.
- Детали, профиль, вход и секции сохраняют существующие переходы.
  Подключение экрана деталей к API не входит в #19058.

Спецификация: [Events & Clubs](specs/events.yaml).
Требования: [#18110](https://ai.nsu.ru/issues/18110), [#18111](https://ai.nsu.ru/issues/18111).
Оформление основано на [вайрфрейме #18899](https://github.com/tusumba/design/blob/c94c8d65613c8365c5aab1f21bdd55d2a66e7f6e/split%201/Tusumba_Wireframes_Preview.html).

Поиск сохранён и передаёт `query` по OpenAPI. В проверенной реализации
`events-service/main` этот параметр пока не обрабатывается; поиск относится
к отдельному требованию #18112. Локальная заглушка поддерживает `query` для проверки клиента.

### Локальный запуск без стенда

Нужен Python 3.9+, без дополнительных пакетов. Из корня проекта:

```bash
python3 scripts/catalog_stub.py
```

Заглушка слушает только `127.0.0.1:8080` и содержит 48 демонстрационных событий.
Даты вычисляются относительно дня запуска. По умолчанию доступны 24 будущих события:
две страницы (20 + 4). Прошедшие имеют статусы «Состоялось» / «Не состоялось»
и доступны при выборе соответствующего диапазона дат.

С запущенным Android-эмулятором выполните в другом терминале:

```bash
bash ./gradlew --no-daemon assembleDebug testDebugUnitTest
adb -e install -r app/build/outputs/apk/debug/app-debug.apk
adb -e shell am force-stop com.example.tusumba
adb -e shell am start -n com.example.tusumba/.MainActivity
```

Debug-сборка уже использует `http://10.0.2.2:8080/` — адрес компьютера из эмулятора.
Когда появится настоящий стенд, укажите URL шлюза до `/v1`:

```bash
bash ./gradlew installDebug -PapiBaseUrl=https://stand.example.org/
```

Параметр применяется к debug-сборке. URL release-сборки пока остаётся существующей
заглушкой `https://api.tusumba.example/` до предоставления адреса стенда.

### Проверка фильтров и состояний

1. Откройте каталог: проверьте загрузку, карточки, «Найдено: 24».
2. «Показать ещё» добавляет последние четыре карточки, кнопка исчезает.
3. Выберите «Платные», раскройте дополнительные фильтры, введите «парк» в место,
   выберите «Подтверждено» и «Не подтверждено», ограничьте даты.
   Останутся платные события в парке, соответствующие всем выбранным фильтрам.
4. Введите несуществующее место: «По выбранным фильтрам ничего не найдено.».
   «Сбросить фильтры» возвращает полный каталог с первой страницы.
5. Конечная дата раньше начальной вызывает сообщение о диапазоне; запрос не отправляется.
6. Проверьте переход к деталям и возврат, профиль, секции, светлую и тёмную темы.

Для других состояний остановите заглушку через Ctrl+C и запустите один вариант:

```bash
python3 scripts/catalog_stub.py --scenario empty
python3 scripts/catalog_stub.py --scenario error
python3 scripts/catalog_stub.py --fail-page 2
python3 scripts/catalog_stub.py --delay 2
```

После смены сценария перезапустите приложение. В `empty` показывается
«мероприятий пока нет.». В `error` проверьте ошибку загрузки; с выбранными фильтрами —
«Не удалось применить фильтры. Попробуйте позже.». Чтобы проверить восстановление,
перезапустите заглушку без параметров и нажмите «Повторить».
`--fail-page 2` проверяет сохранение карточек при ошибке дозагрузки.
Старый параметр сборки `catalogMockScenario` больше не используется: каталог
всегда работает по HTTP, сценарий выбирается на стороне заглушки.

Тесты MockWebServer проверяют HTTP-параметры, статусы, пагинацию, декодирование и ошибки.
Тесты ViewModel — отмену запросов, смену/сброс фильтров, повтор страниц;
Compose-тесты — элементы управления и состояния экрана.

## Каталог и страницы секций (#19060)

Пункт «Секции» в нижней навигации открывает каталог из Events & Clubs.
Поиск по части названия передаётся в `GET /v1/clubs?query=...`. Очистка возвращает
исходный каталог. «Показать ещё» загружает следующую страницу.

Карточка открывает `GET /v1/clubs/{id}`. На странице показаны название, описание,
расписание, место встреч, контакты и мероприятия из `GET /v1/events?club_id=...`.
Мероприятия используют существующие карточки и переход к деталям мероприятия.
При HTTP 404 отображается сообщение «Секция недоступна.»

По умолчанию debug-сборка использует локальный шлюз `http://10.0.2.2:8080/`.
Для другого стенда замените адрес в следующей команде.

```bash
bash ./gradlew installDebug -PapiBaseUrl=https://stand.example.org/
```

Параметр задаёт базовый адрес шлюза с префиксом до `/v1`.
Для локального HTTP-сервера в debug разрешён cleartext-трафик.
Ошибки каталога, поиска, страницы и списка мероприятий имеют отдельные действия
повторной загрузки.

## Страница мероприятия и запись (#19059)

Страница загружает `GET /v1/events/{id}`: название, описание, дату, место, цену и
организатора. Для секции имя берётся из Events, для пользователя — из публичного
профиля Identity. Дополнительные сведения об организаторе и друзьях не блокируют
страницу при недоступности их сервисов. Если данные о друзьях доступны в Ticketing,
отображаются их публичные имена и статусы; пустой список скрывается.

«Показать на карте» передаёт адрес внешнему приложению через `geo:`. Если приложения
карт нет, открывается поиск адреса в браузере. Доступ к геолокации не требуется.

Для бесплатного будущего мероприятия доступны «Пойду» и «Интересно». Перед отправкой
можно выбрать видимость: «Все», «Только друзья», «Анонимно». Статус и видимость
сохраняются одним `PUT /v1/events/{id}/registration`. Повторное сохранение изменяет
существующую запись. Пока запрос выполняется, повторная отправка заблокирована.

Существующая запись находится через страницы `GET /v1/me/registrations`: отдельного
GET для записи одного мероприятия в контракте нет. Экран показывает текущие статус
и видимость, перечитывает их после возврата из «Моих записей», сохраняет видимость
при изменении статуса. Если проверить существующую запись не удалось, доступен
повтор загрузки, чтобы случайно не изменить её настройки.

По OpenAPI Ticketing анонимность скрывает имя вошедшего пользователя от других
пользователей и организатора. Запись гостя без входа контрактом не предусмотрена:
гостю предлагается войти. Покупка платных билетов описана в API как черновик для
Спринта 3, поэтому «Купить билет» пока недоступна. Ошибки и закрытая запись
отображаются по требованиям [#18113](https://ai.nsu.ru/issues/18113) и
[#18115](https://ai.nsu.ru/issues/18115).

### Запуск без общего стенда

Нужен Python 3.9+, без дополнительных пакетов. Из корня Android-репозитория:

```bash
python3 scripts/event_detail_stub.py
```

Заглушка слушает только `127.0.0.1:8080`, поддерживает Events, публичные профили,
записи, друзей и проверочный список участников. Она использует демонстрационный
токен существующей моковой авторизации приложения, а не настоящую проверку JWT.
Записи хранятся в памяти до остановки процесса. Одновременно запускайте одну
заглушку на этом порту.

В другом терминале, с запущенным Android-эмулятором:

```bash
bash ./gradlew --no-daemon assembleDebug testDebugUnitTest
adb -e install -r app/build/outputs/apk/debug/app-debug.apk
adb -e shell am force-stop com.example.tusumba
adb -e shell am start -n com.example.tusumba/.MainActivity
```

Debug URL по умолчанию — `http://10.0.2.2:8080/`. Для другого шлюза можно задать
`-PapiBaseUrl=https://stand.example.org/` при сборке. Release URL пока остаётся
существующей заглушкой `https://api.tusumba.example/`.

1. Откройте «Научный лекторий» из демокаталога. Проверьте данные, организатора и карты.
   ID заглушки совпадают с демокаталогом; даты на странице вычисляются от дня запуска.
2. Гостю предлагается войти. Используйте демонстрационный логин `demo` и пароль
   `Tusumba123!`. После входа приложение возвращается на страницу мероприятия.
3. Выберите «Анонимно» и «Пойду». Проверьте сообщение о сохранении и текущую запись.
4. Откройте «Мои записи», затем вернитесь на мероприятие. Измените статус на
   «Интересно», проверьте, что видимость осталась анонимной.
5. Отмените запись в «Моих записях» и вернитесь: прежний статус исчезнет.
6. Проверьте платное мероприятие и обе системные темы.

Для проверки представления участника организатору заглушка принимает отдельный
демонстрационный токен. После записи на лекторий:

```bash
curl -H 'Authorization: Bearer stub-organizer' \
  http://127.0.0.1:8080/v1/events/9f1e6a52-3c4b-4d7e-8a10-000000000004/participants
```

В анонимном режиме `user_id` равен `null`; при публичной записи заполнен.
Обычному пользователю список участников недоступен (403).

Другие сценарии: остановите заглушку через Ctrl+C и запустите один вариант:

```bash

python3 scripts/event_detail_stub.py --scenario unavailable
python3 scripts/event_detail_stub.py --scenario error
python3 scripts/event_detail_stub.py --scenario closed
python3 scripts/event_detail_stub.py --scenario registration-error
python3 scripts/event_detail_stub.py --scenario unauthorized
python3 scripts/event_detail_stub.py --delay 2
```

После смены сценария перезапустите приложение. Для проверки восстановления запустите
заглушку без параметров и нажмите «Повторить» на экране ошибки.

Общего стенда нет, серверная авторизация Android пока заменена моками. Проверка
настоящей записи с телефона и её отображения настоящему организатору остаётся
шагом приёмки после готовности этих зависимостей.

## Подача и отслеживание заявок (#18090, #18098)

Профиль → «Мои заявки» → «Подать заявку». Доступны два типа: мероприятие
и страница секции. Форма мероприятия содержит название, описание, дату,
место и признак бесплатного входа либо цену в рублях. Организатором выступает
текущий пользователь. Форма секции содержит название, описание, место,
расписание и контакты Telegram/email. Обязательность и ограничения полей
соответствуют `specs/moderation.yaml`. Подача от имени секции (`club_id`)
относится к отдельному сценарию #18102 и здесь не добавлена.

Используется сгенерированный ApplicationsApi:

- `POST /v1/applications` — отправка в Moderation;
- `GET /v1/me/applications?page=...&size=20` — список, новые первыми;
- `GET /v1/me/applications/{id}` — состояние и комментарий модератора.

Ошибки обязательных полей, длины текста, даты и цены показаны у полей.
Цена переводится в целые копейки без округления. Серверные ошибки 422
из `error.details` привязываются к полям; 409 `application_duplicate`
показывает сообщение об активной заявке. Повторная отправка во время запроса
заблокирована; окончательную проверку дублей выполняет Moderation.
При ошибке введённые данные сохраняются до ухода с формы.

Список поддерживает «Показать ещё», обновление при возврате и ручное обновление.
В карточке доступны статус, данные заявки, даты и комментарий модератора.
Одобренная заявка с `result_object_id` открывает мероприятие или секцию.
Создание объекта и назначение владельца выполняют серверы Moderation и Events
через ApplicationApproved; Android не создаёт объект напрямую и не выдаёт права.

Для действительной отправки AuthModule теперь использует существующий
NetworkAuthRepository: вход и регистрация идут в Identity, JWT сохраняется
для общего AuthInterceptor/TokenAuthenticator. Ранее описанные инструкции
демо-входа с MockAuthRepository относятся к старой конфигурации и больше
не применяются к обычной сборке. После старого демо-входа следует выйти
и войти с учётной записью Identity на выбранном стенде.

Локальные проверки без внешних сервисов:

```powershell
.\gradlew.bat testDebugUnitTest assembleDebug --offline
```

MockWebServer проверяет контракт POST/GET, пагинацию, комментарий модератора,
серверную валидацию и ошибки. Тесты ViewModel проверяют повторную отправку,
смену аккаунта, защиту от запоздавшего ответа и повтор страницы после ошибки.
Compose-тесты проверяют переключение формы, ошибки полей, блокировку отправки
и комментарий отклонённой заявки.

Проверка приёмки на общем стенде (в рамках этой доработки не выполнялась):

1. Собрать с `-PapiBaseUrl=https://<адрес-шлюза>/`, войти через Identity.
2. Отправить с телефона заявку каждого типа; проверить её в веб-очереди модератора.
3. Отклонить заявку с комментарием, обновить карточку на телефоне.
4. Отправить повторную активную заявку с теми же названием и датой: проверить 409.
5. Одобрить заявку, дождаться обработки ApplicationApproved и открыть объект
   из карточки; проверить на сервере членство автора с ролью owner или club_admins.

Редактирование существующего мероприятия (`PATCH /v1/events/{id}`) является
отдельным сценарием UC-15 и не входит в перечисленный объём экранов заявок.
Трудозатраты во внешний трекер не вносились: пользователь запретил обращения
к внешним сервисам.
